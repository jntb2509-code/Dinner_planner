# מתכנן הארוחות המשפחתי

כלי לתכנון ארוחה משותפת כשלכל אחד יש העדפות אחרות.
כל משתתף ממלא בלינק אחד מה הוא לא יכול לאכול, מה הוא לא אוהב ומה הוא אוהב —
והטבח מקבל תמונה אחת: מי יכול לאכול מה, מי עלול להישאר בלי כלום, ומה כדאי
להוסיף לתפריט כדי לסגור את הפער.

---

## איך זה עובד (בקצרה)

**קבוצה** היא רשימת אנשים קבועה — המשפחה. כל אחד ממלא את ההעדפות שלו
**פעם אחת**, והן חיות בקבוצה ולא באירוע ספציפי. **ארוחה** היא רק "מי
מהם מגיע הפעם ומה מבשלים", ולכן דוח הכיסוי מוכן ברגע שפותחים אותה —
בלי לחכות לאף אחד. אפשר לפתוח כמה קבוצות נפרדות.

עדכון של אדם בקבוצה משתקף מיד בכל הארוחות שהוא מוזמן אליהן.

**הכתובת הראשית היא לוח הבקרה.** המכשיר זוכר לאילו קבוצות יש לך גישה,
כך שאין צורך לשמור לינקים: פותחים את הכתובת ורואים את הקבוצות. הלינק
הפרטי נשאר בלשונית ״הזמנה״ כגיבוי למעבר מכשיר.


שלוש דרגות העדפה, שמתנהגות שונה לגמרי:

| דרגה | דוגמאות | התנהגות |
|---|---|---|
| **חסימה מוחלטת** | אלרגיה, כשרות, צמחונות | המנה לא קיימת עבור האדם הזה |
| **לא אוהב** | "לא בקטע של חצילים" | נספר ככיסוי, אבל לא ככיסוי טוב |
| **אוהב במיוחד** | "מת על סלמון" | בונוס לדירוג, לא אילוץ |

המרכיבים מסודרים בהיררכיה, כך שחסימת "אגוזים" חוסמת אוטומטית שקדים, פקאן
וקשיו. **בוטנים נמצאים מחוץ לענף הזה במכוון** — אלרגיה לבוטנים ואלרגיה
לאגוזי עץ הן שתי אלרגיות נפרדות.

הכלל שהמערכת אוכפת: לכל משתתף חייבות להיות לפחות N מנות שהוא יכול לאכול,
ולפחות אחת מהן מנה עיקרית. הסף ניתן לשינוי בעת יצירת הארוחה.

## העלאה לאוויר (Vercel) — צעד אחר צעד

1. היכנס ל־[vercel.com](https://vercel.com) והתחבר עם חשבון ה־GitHub שלך.
2. לחץ **Add New → Project**, בחר את הריפו הזה ולחץ **Deploy**.
   הבנייה לוקחת כדקה. בסופה תקבל כתובת כמו `dinner-planner.vercel.app`.
3. **חשוב** — כדי שהנתונים לא ייעלמו, חבר מסד נתונים:
   בפרויקט → לשונית **Storage** → **Create Database** → בחר **Postgres**
   (Neon) → **Connect**.
   Vercel יגדיר את משתנה הסביבה `DATABASE_URL` לבד, והאפליקציה תזהה אותו
   ותתחיל להשתמש בו. הטבלה נוצרת אוטומטית בפעם הראשונה.
4. לחץ **Redeploy** כדי שהפריסה תרים את החיבור החדש.

זהו. פתח את הכתובת, צור ארוחה, ושלח את הלינק למשפחה.

### חשוב: עבוד תמיד מכתובת הייצור

ל-Vercel יש שתי סוגי כתובות. כתובת הייצור (`<פרויקט>.vercel.app`) פתוחה
לכולם. כתובת של פריסה ספציפית — זו עם הגיבוב האקראי, שאליה מגיעים
בלחיצה על **Visit** מתוך עמוד פריסה — **מוגנת בדרישת התחברות ל-Vercel**.

האפליקציה בונה את לינקי השיתוף מכתובת הייצור בלבד, כך שלינק שנוצר בטעות
מכתובת פריסה עדיין יעבוד לכל המשפחה. אם בכל זאת בן משפחה מתבקש להתחבר
ל-Vercel, בדוק ב-**Settings → Deployment Protection** ש-Vercel Authentication
אינו מוגדר ל-All Deployments.

אם הוספת דומיין משלך, הגדר את `NEXT_PUBLIC_BASE_URL` (למשל
`https://arucha.example.com`) והלינקים ייבנו ממנו.

> **שלב 3 אינו אופציונלי.** מערכת הקבצים של Vercel היא לקריאה בלבד, ולכן
> בלי מסד נתונים האפליקציה תיטען אבל כל ניסיון ליצור ארוחה ייכשל. במצב
> הזה היא תציג הודעה מפורשת שמפנה אותך לכאן.

> **הרצה מקומית היא סיפור אחר** — שם אין `DATABASE_URL`, הנתונים נשמרים
> בקובץ `data/events.json`, והכל עובד בלי שום הגדרה.

## הרצה על המחשב שלך

```bash
npm install
npm run dev        # http://localhost:3000
```

בלי `DATABASE_URL` הנתונים נשמרים בקובץ `data/events.json` — אפס הגדרות.

```bash

```

## פרטיות

- אין הרשמה ואין סיסמאות. הגישה היא דרך לינקים.
- **לינק הקבוצה** (`/h/<id>`) מראה רק את שם הקבוצה ומי כבר הצטרף. הוא לא
  חושף את ההעדפות של אף אחד.
- **הלינק הפרטי** (`/h/<id>/manage?t=<token>`) חושף הכל, כולל אלרגיות. אל
  תשתף אותו בקבוצה. הוא מתקף גם כל ארוחה של הקבוצה, כדי שלא יהיה צורך
  בלינק נפרד לכל ארוחה.
- לארוחה בודדת יש טוקן משלה, למקרה שרוצים למסור תכנון של ארוחה אחת בלי
  לתת גישה לכל הקבוצה.
- מי שיש לו את לינק המשפחה יכול למלא טופס. זה מתאים לקבוצה סגורה, לא
  לפרסום פומבי.

## מבנה הקוד

```
src/core/       מנוע ההתאמה — לוגיקה טהורה, בלי תלות בממשק או במסד נתונים
  taxonomy.ts   היררכיית המרכיבים והדיאטות
  matching.ts   הערכת מנה מול משתתף, מטריצה, דוח כיסוי
  suggest.ts    השלמת חורים בתפריט
  library.ts    מאגר מנות התחלתי מתויג
src/lib/        מודל הקבוצות, אחסון (קובץ מקומי / Postgres) וולידציה
src/app/        הממשק ו־API
  globals.css   מערכת העיצוב: צבע, מרווחים, טיפוגרפיה, צורה
```

`src/core` הוא הליבה. אפשר להחליף את הממשק, את מסד הנתונים או את מנוע
ההצעות בלי לגעת בו — ולהפך.

## שינוי מראה האתר

כל החלטה חזותית חיה ב-`globals.css`: פלטת הצבעים, סקאלת המרווחים,
הטיפוגרפיה, הפינות והצללים — כולן משתני CSS בראש הקובץ.

**אין `style` מוטבע בקוד הרכיבים.** זה מכוון: החלטה עיצובית שקבורה בתוך
JSX מחייבת לעבור על כל הקבצים כדי לשנות אותה. כאן, שינוי הפלטה או
עיגול הפינות בכל האתר הוא עריכה של כמה שורות בקובץ אחד.

אם מוסיפים רכיב חדש — הוסיפו לו מחלקה ב-`globals.css` במקום `style`.

## מה עוד מתוכנן

- **זהות בין מכשירים** — מי אתה בקבוצה נשמר ב-localStorage, אז עדכון
  ההעדפות שלך מתאפשר רק מאותו מכשיר שבו הצטרפת. פרופיל שעובר בין
  מכשירים הוא השלב הבא.
- **מתכונים** — הטקסונומיה תוכננה כך שכל מקור מתכונים (מאגר משלנו, API
  חיצוני, או יצירה עם AI) יתחבר אליה. חובה: אימות רשימת המרכיבים של כל
  מתכון מול הטקסונומיה לפני הצגה — לא מסתמכים על מודל שפה בענייני אלרגיה.
- **כמויות** — כמה להכין מכל מנה, לפי כמה אנשים באמת יאכלו ממנה.
